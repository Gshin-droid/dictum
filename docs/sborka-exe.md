# Как Dictum собирается в exe и почему именно так

> **In English:** *How Dictum is packed into an exe, and why that way.* Design
> notes on the build: the five PyInstaller traps that catch anyone packing a
> Python speech-recognition program into a single file, what was chosen and what
> was rejected. Russian only — [main README in English](../README.md).

Разбор решений сборки: что выбрано, что отвергнуто и на какие грабли наступает
всякий, кто пакует Python-программу с распознаванием речи в один файл.

## Зачем вообще собирать

Программа на Python требует от получателя установить Python, создать venv и
выполнить `pip install`. Три непонятных шага — и главная причина не начать
пользоваться вовсе. Собранный exe убирает их полностью: скачал, запустил.

## Модель лежит снаружи, а не внутри exe

Веса весят 216 МБ, и вшить их внутрь технически можно. Но однофайловая сборка
(`--onefile`) при **каждом** запуске распаковывает всё своё содержимое во
временную папку. С моделью внутри старт растянулся бы до десятка секунд, и так
каждый раз. Снаружи распаковываются только библиотеки — старт 1–3 секунды.

Поэтому веса живут в папке `models/` рядом с exe. Папки нет — они туда
скачиваются при первом запуске и больше не качаются никогда.

## Два способа поставки

| | Размер | Первый запуск |
|---|---|---|
| `dictum.exe` | 60 МБ | качает модель, несколько минут |
| `dictum-portable.zip` | 209 МБ | сразу готов, сеть не нужна |

Второй собирается тем же скриптом с флагом `--portable`: exe, уже скачанная
модель и `Прочти меня.txt` в одной папке, сжатые в архив. Он для машины без
интернета, с медленным или платным — и для флешки.

Один способ вместо двух не годится: без интернета первый вариант бесполезен, а
209 МБ ради программы «попробовать» скачает не всякий.

## Пути считаются от программы, а не от исходника

Единственное принципиальное изменение в коде ради сборки. Обычно корень проекта
вычисляют от файла с кодом — но внутри exe этого файла не существует.

```python
def _app_dir() -> Path:
    if getattr(sys, "frozen", False):   # признак, который ставит PyInstaller
        return Path(sys.executable).resolve().parent
    return Path(__file__).resolve().parent
```

От `APP_DIR` считаются `models/`, `.env`, `logs/`, `data/dictation/`. Следствие:
папку с программой можно унести на флешке целиком, ничего не сломав.

## Пять ловушек PyInstaller

Каждая найдена только на живом exe. При обычном запуске из исходников ни одна не
воспроизводится — это главное, что стоит знать: **проверять сборку можно только
собранной программой**.

**1. `sys.stdout` в сборке без консоли — не пустой.** Это заглушка, молча
глотающая вывод. Проверка `if sys.stdout is None` оказывается ложной, вывод
уходит в никуда, и первый exe работал, но выглядел мёртвым: ни строчки в журнале.
Проверять надо признак сборки:

```python
if getattr(sys, "frozen", False) or sys.stdout is None:
```

**2. Библиотека спрашивает свой номер версии.** `onnx_asr` при старте читает
собственные метаданные через `importlib.metadata`, а PyInstaller паспорта пакетов
(`.dist-info`) без спроса не кладёт. Падает на первой же строке:
`PackageNotFoundError`. Лечится `--copy-metadata onnx-asr onnxruntime numpy`.

**3. Данные библиотек не находятся сами.** Тридцать служебных моделей
предобработки звука внутри `onnx_asr` и библиотека записи PortAudio внутри
`sounddevice` — это не код, анализатор импортов их не видит. Нужны
`--collect-data onnx_asr`, `--collect-all sounddevice`,
`--collect-binaries onnxruntime`.

**4. Импорт внутри функции невидим.** `voice_window` и `voice_settings`
импортируются не сверху файла, а внутри функций — так задумано, чтобы окно можно
было не грузить в headless-режиме. Статический анализатор такие импорты не
находит: нужны `--hidden-import`.

**5. Работающий exe держит сам себя.** Пересборка падает на «отказано в доступе».
Скрипт сборки сначала останавливает запущенные экземпляры.

## Антивирусы

Программа ставит низкоуровневый перехват клавиатуры — технически то же самое, что
делает клавиатурный шпион. В упакованном неподписанном exe это классический повод
для тревоги, и не потому что кто-то ошибся, а потому что признак настоящий.

Что сделано, чтобы уменьшить шум:

- **сжатие UPX выключено** (`--noupx`): оно почти ничего не экономит, зато само
  по себе служит поводом для срабатывания;
- **лишние библиотеки исключены** — `torch`, `faster_whisper`, `ctranslate2` могли
  бы приехать транзитом через чужие зависимости и утроить размер;
- **у файла есть паспорт** (`--version-file`): имя, версия, автор, лицензия. Exe
  без паспорта выглядит безымянным куском кода — и для человека в проводнике, и
  для эвристики.

Чем это не лечится: подписью кода. Сертификат стоит 200–400 долларов в год, и для
бесплатной программы покупать его смысла нет. Отсюда же SmartScreen при первом
запуске — в README есть, что нажать.

Проверка выпуска — `release_check.py`: спрашивает VirusTotal об отпечатке
собранного файла и печатает вердикты движков. Загрузка спрятана за отдельный флаг,
потому что файл остаётся у них навсегда.

## Чем доказывается, что сборка живая

Не «собралось без ошибок», а:

- `dictum.exe --check` находит микрофон и грузит модель;
- запуск без ключей: в журнале строка «Готов», у часов появился значок;
- диктовка в Блокнот вставляет текст;
- архив распаковывается **в другую папку** и работает оттуда — это проверка, что
  пути считаются от exe, а не зашиты при сборке;
- в журнале распакованной копии стоит «Загружаю из models/», а не «Скачиваю» —
  доказательство, что переносная копия действительно не ходит в сеть.
